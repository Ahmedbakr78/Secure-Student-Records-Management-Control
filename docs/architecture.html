System map

One request. Seven boundaries.

SRMS is a local-first desktop application with a Tkinter presentation layer, a Python security kernel, a parameterised data-access layer, and two storage backends. Each boundary has a defined responsibility — and a documented limit.

Layered design

The intended path for protected operations.

The diagram separates presentation, the application security kernel, data access, and storage. The audit writer observes authentication, denials, writes, and workflow events.

The path is the intent, not a claim of universal enforcement.Some existing GUI paths call models directly; the kernel is most consistently applied where data crosses from a dashboard into a model or authentication service. This is documented as a limitation.

Layers

Presentation, policy, persistence.

Each layer has a distinct job. The presentation layer explains decisions; it is not trusted to make the final one.

Presentation layer

Login, role dashboards, profile management, security status, analytics, and a read-only browser viewer. The UI translates a policy result into a clear outcome or denial reason.

Request lifecycle

From credentials to an audited result.

The sequence below is the reference path for a protected operation. Denials stop the path and return a reason instead of silently doing nothing.

  1. Authenticate

    Verify the user, state, hash, and salt. Record success or failure and open the role dashboard.

  2. Authorise

    Check the role, table, operation, ownership, assignment, or publication restriction.

  3. Check clearance

    Apply No Read Up for reads and No Write Down for writes, with the Admin exception made explicit.

  4. Constrain aggregates

    Reject undersized result sets, stricter MIN/MAX queries, and tracker patterns that narrow a population.

  5. Control flow

    Decide whether display, export, print, copy, save, or clipboard use is allowed for the classification.

  6. Protect and persist

    Decrypt only for an authorised view. Encrypt sensitive values before writes. Use parameters for every value.

  7. Audit

    Record the actor, role, target, classification, outcome, and explanation for reconstruction.

REFERENCE PATH

Denial is a feature

A blocked action returns a specific reason: RBAC permission, MLS direction, inference threshold, flow policy, or encryption failure.

That makes the model teachable and the tests repeatable. It also means a reviewer can distinguish “not implemented” from “deliberately denied.”

Run it locally

From checkout to a reproducible demo.

The primary path uses SQL Server 2022 in Docker. A SQLite fallback gets the desktop client running without a database server, with reduced security properties. Every command below assumes the repository root.

Python 3.10+ Docker SQL Server 2022 SQLite fallback

Local demonstration only.The setup uses the published classroom password Srms@2024! and the SA account. Replace them before doing anything beyond a local demo. Never load real student records.

Primary path

SQL Server in five steps.

This path preserves the database role mirrors, secure views, stored procedures, and certificate-backed encryption hierarchy.

Clone and enter the repository

If you already have a local copy, open a terminal in its root instead.

terminal
git clone https://github.com/Ahmedbakr78/Secure-Student-Records-Management-Control.git
cd Secure-Student-Records-Management-Control

Start SQL Server 2022

Wait for the container to report that it is ready for client connections.

terminal
docker run \
  -e 'ACCEPT_EULA=Y' \
  -e 'MSSQL_SA_PASSWORD=Srms@2024!' \
  -p 1433:1433 \
  --name sqlserver2022 \
  --hostname sqlserver \
  -d mcr.microsoft.com/mssql/server:2022-latest

docker ps --filter name=sqlserver2022
docker logs --tail 50 sqlserver2022

Create the database and load the scripts

Run the scripts in order. Stop at the first error rather than loading a partial schema.

terminal
docker exec -it sqlserver2022 \
  /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C \
  -Q "IF DB_ID('SRMS_SecureDB') IS NULL CREATE DATABASE SRMS_SecureDB;"

docker exec -i sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C -d SRMS_SecureDB \
  < sql/sqlserver_schema.sql

docker exec -i sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C -d SRMS_SecureDB \
  < sql/sqlserver_roles.sql

docker exec -i sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C -d SRMS_SecureDB \
  < sql/sqlserver_views.sql

docker exec -i sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C -d SRMS_SecureDB \
  < sql/sqlserver_procedures.sql

docker exec -i sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C -d SRMS_SecureDB \
  < sql/sqlserver_sample_data.sql

Install Python dependencies

Activate the virtual environment before installing requirements.

terminal
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt

Set a development key and launch

Set a unique encryption secret. The fallback key is published and must not protect real data.

terminal
export SRMS_MASTER_KEY="replace-with-a-long-random-secret"
python src/gui/main.py

Existing container or busy port?Use docker start sqlserver2022. If port 1433 is occupied, map a different host port and update SQLSERVER_CONFIG['port'] in src/database/connection.py.

Alternatives

Restore, fall back, or inspect.

Restore the backup

The repository includes SRMS_SecureDB.bak. Copy it into the container and restore with REPLACE.

terminal
docker cp SRMS_SecureDB.bak \
  sqlserver2022:/var/opt/mssql/backup/

docker exec -it sqlserver2022 \
  /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P 'Srms@2024!' -C \
  -Q "RESTORE DATABASE SRMS_SecureDB FROM DISK='/var/opt/mssql/backup/SRMS_SecureDB.bak' WITH REPLACE;"

If logical file paths conflict, inspect with RESTORE FILELISTONLY and add MOVE clauses.

Use the SQLite fallback

Useful when SQL Server is unavailable. Set the backend type, confirm database/srms.db exists, and launch the same GUI.

src/database/connection.py
DATABASE_TYPE = 'sqlite'
terminal
export SRMS_MASTER_KEY="replace-with-a-long-random-secret"
python src/gui/main.py

No stored procedures, database roles, secure views, or SQL Server encryption hierarchy.

Read-only viewer

Inspect the database from localhost.

The Flask viewer is a review tool, not an authenticated application. It uses allow-listed tables and read-only queries, and it must remain bound to localhost.

terminal
python db_viewer.py
# open http://127.0.0.1:5000

Do not expose port 5000.The viewer has no application authentication. Network exposure would bypass the role model.

Checklist

Know when the environment is ready.

  • Python 3.10+ and Tkinter are available.
  • The virtual environment is active.
  • Requirements are installed.
  • SQL Server is healthy, or SQLite is selected.
  • SRMS_SecureDB exists.
  • Schema, roles, views, procedures, and sample data loaded in order.
  • SRMS_MASTER_KEY is set for development.
  • Login works for Admin, Student, and Guest.
  • The Flask viewer loads on localhost only.
  • Demo credentials are understood to be public.
  • No real student data is present.
  • The security test matrix is ready to record evidence.
